# 参数化紧固件后续发展路线

> 基于版本：0.30.0  
> 文档目标：规划插件在易用性、操作效率、视觉品质和产品成熟度方面的后续发展。  
> 不包含：打印机校准、材料补偿标定或社区打印参数共享。

## 1. 当前产品判断

参数化紧固件已经具备较完整的工作闭环：

- 支持杯头、沉头、六角头螺丝、普通/尼龙防松六角螺母和热熔螺母。
- 支持螺纹咬合、只咬合、螺母固定三种装配方式。
- 支持智能预览放置、经典放置、模板式单点/批量更新和组件生命周期维护。
- 支持非破坏式 Rhino、STEP、STL 输出，以及统计和 Excel 清单。
- 支持浅色/深色主题、紧凑面板、复制变换和旧模型迁移。

下一阶段不宜继续把新功能简单堆进主面板。产品应从“功能齐全”转向“高频操作极快、复杂状态易懂、长期使用稳定”。核心竞争力应是：

1. 在视口中完成大多数操作，减少面板与模型之间来回移动。
2. 把一组参数升级为可复用的装配模板，减少重复设置。
3. 让批量布置、批量修改和问题定位具备明确、可预测的工作流。
4. 让插件在不同窗口宽度、主题和复杂文档中保持统一、克制的视觉品质。

## 2. 产品设计原则

### 2.1 高频操作靠近模型

放置、改长度、改规格、改嵌入、翻转方向等高频动作应优先在视口中完成。主面板负责模板、精确数值和高级设置。

### 2.2 默认简单，复杂能力按需展开

新建时只显示当前装配方式需要的参数。高级切割、架桥、输出开关和诊断信息按场景出现，避免所有设置同时展示。

### 2.3 先显示结果，再要求确认

参数变化应立即更新虚拟紧固件、孔径、孔深和宿主角色。任何失败都应指出具体对象、原因和可执行修复建议。

### 2.4 模板与场景对象严格分离

面板模板始终代表“下一次放置或更新要使用的数据”；场景选择只代表目标。只有“读取组件”才用场景数据替换模板。

### 2.5 非破坏性与可恢复性优先

放置、更新、复制、导出和自动修复均应保持一次 Undo、失败零写入和旧模型可迁移。

| P0 | 装配模板与最近使用 | 显著减少重复设置 | 中 | 0.30 |
| P1 | 批量布置与阵列工作流 | 提高多孔设计效率 | 中高 | 0.31 |
| P1 | 组件导航与问题中心 | 提升复杂文档可控性 | 中 | 0.31 |

## 4. 第一阶段：让修改更快（建议 0.30）

> 实现状态：已在 0.30.0 完成。已交付视口快速编辑器、显式参数手柄、最近/收藏模板、模板 JSON 管理、重复上一放置与重复上一更新；共享预检与提交协调器同步成为后续阶段基础设施。

### 4.1 视口快速编辑器

选中一个控制点后，在控制点附近显示轻量浮动编辑条，不打开新的大窗口。建议只提供：

- 规格切换。
- 长度输入及常用长度快捷项。
- 嵌入深度输入与 `0 / 齐平或全埋`。
- 装配方式切换。
- 翻转方向。
- 更新、读取和删除。

浮动编辑条只显示当前类型适用的字段；按 Esc 取消，Enter 应用。精细孔参数仍在主面板修改。

### 4.2 视口参数手柄

为单选组件增加可选的几何手柄：

- 螺杆末端手柄：拖动修改长度，并吸附常用长度。
- 头部手柄：拖动修改嵌入深度。
- 螺母手柄：拖动修改末端露出量。
- 旋转环：控制六角槽或架桥方向。

拖动时显示实时尺寸标签，松开前只生成预览，松开后一次提交。手柄应可关闭，避免干扰普通 Rhino Gumball。

### 4.3 最近使用与收藏模板

在主面板顶部增加不超过 5 个最近模板，并允许收藏常用组合。例如：

- `M3×12 杯头 · 通孔+咬合 · +1D`
- `M4×20 沉头 · 螺母固定 · 露出2`
- `M3 热熔螺母 · Ø4.6×5`

模板保存紧固件、装配方式和切割工艺，不保存宿主对象、位置或控制点。支持重命名、复制、排序和导入/导出 JSON。

### 4.4 重复上一操作

增加“重复上一放置”和“重复上一更新”命令：

- 重复放置直接进入智能预览，不重新设置参数。
- 重复更新把上一次成功模板应用到当前选中控制点。
- 在命令行和 Tooltip 中明确即将使用的模板摘要。

## 5. 第二阶段：让批量设计更高效（建议 0.31）

### 5.1 批量点位放置

允许先选择 Rhino Point、曲线端点、圆心或点集，再一次生成多颗紧固件：

- 统一使用当前模板。
- 每个点独立识别面、轴向和宿主。
- 生成前显示成功、警告、失败数量。
- 任一点失败时可选择“全部取消”或“只创建有效项”。

建议同时支持从圆、圆弧和圆柱面中心提取放置点，减少手工创建辅助点。

### 5.2 阵列感知工作流

对线性阵列、矩形阵列和极轴阵列提供参数化批量放置入口：

- 使用 Rhino 现有阵列结果或点阵作为输入。
- 保留每颗组件独立 ID，便于局部修改。
- 允许批量改变规格，同时保持各自位置和宿主。
- 阵列源变化时提供“重新匹配点位”，不自动静默移动组件。

### 5.3 选择过滤器与组件导航器

增加可停靠的紧凑导航器，按以下维度筛选控制点：

- 类型、规格、装配方式。
- 有效、待重绑、导出关闭、隐藏预览。
- 宿主、图层、用户标签。
- 普通螺母、防松螺母、配套螺母。

点击列表定位并闪烁对应控制点；双击缩放到对象；可把筛选结果直接作为批量更新或统计范围。

### 5.4 批量更新预检面板

批量更新前显示简洁差异摘要：

- 将修改多少颗组件。
- 哪些字段会统一。
- 哪些宿主关系和开关会保留。
- 哪些组件会新增、移除或改变宿主角色。

仅在高风险变更或失败时展开详细列表，普通批量更新保持一次点击完成。

## 6. 第三阶段：让装配更可靠（建议 0.32）

### 6.1 装配检查器

增加不涉及强度计算的几何检查：

- 螺杆长度是否足以进入目标宿主。
- 螺杆是否超出只咬合宿主。
- 螺母是否完整落入安装槽。
- 螺丝头、螺母或热熔螺母是否与其他实体碰撞。
- 孔与边界、薄壁或相邻孔之间的几何距离是否过小。
- 螺母扳手空间、螺丝刀/内六角工具轴向空间是否被遮挡。

检查结果分为错误、警告和提示；点击问题直接定位对象，并提供“修改长度”“切换模式”“重新绑定”等快捷动作。

### 6.2 自动长度建议

根据当前宿主层叠关系提供候选长度，而不是直接替用户修改：

- 螺纹咬合：满足穿过前宿主并达到设定咬合长度的最短常用规格。
- 只咬合：不超过宿主可用深度的最长或最接近常用规格。
- 螺母固定：满足螺母高度和末端露出量的最短常用规格。

界面显示“当前长度、建议长度、差值”，用户一键采用。该功能只进行几何适配，不做承载能力结论。

### 6.3 装配关系可视化

选中组件时，用短暂、克制的视口叠加显示：

- 蓝色：通孔宿主。
- 橙色：咬合宿主。
- 紫色：螺母槽或安装槽宿主。
- 轴向尺寸链：嵌入、穿过厚度、咬合深度、螺母位置。

叠加信息在取消选择后自动消失，不创建文档对象。

### 6.4 重新绑定向导

把“刷新/清理”拆成更明确的操作：

- 快速刷新：只修复缓存和对象 ID。
- 重新绑定：显示候选宿主及匹配原因，由用户确认。
- 清理残留：只删除缺少控制点的无效组件。

避免一个按钮同时承担修复、重绑和删除，降低用户对破坏性操作的不确定感。

## 7. 第四阶段：让输出与交付更完整（建议 0.32–0.33）

### 7.1 输出中心

把 Rhino、STEP、STL 和物料清单整合为一个独立输出窗口：

- 左侧选择范围：当前选择、当前图层、全部有效宿主。
- 中部预检：有效组件、关闭布尔、待重绑和布尔风险。
- 右侧选择输出：Rhino、STEP、STL、Excel。
- 支持一次生成多个交付文件，并使用一致文件名规则。

主面板仍保留快速导出图标；输出中心用于正式交付。

### 7.2 装配清单升级

在现有 Excel 基础上增加：

- 装配编号和用户备注。
- 每种紧固件的缩略示意图。
- 独立物料、配套物料和总数量。
- 按图层、宿主或用户分组统计。
- 可选 CSV 输出，方便接入采购或项目管理系统。

### 7.3 设计冻结与交付快照

允许创建只读的“交付快照”：

- 保存组件参数哈希、宿主几何哈希和输出时间。
- 后续模型变化时提示哪些紧固件或宿主已与快照不一致。
- 不复制整个 3DM，不替代版本控制，只用于判断是否需要重新输出。

## 8. 第五阶段：扩展标准件能力（建议 0.33 以后）

### 8.1 用户自定义紧固件库

提供受控的自定义预设编辑器：

- 复制现有类型后修改尺寸。
- 为每条尺寸记录名称、来源、版本和备注。
- 导入/导出 JSON 或 CSV。
- 非法尺寸和缺失字段在保存前阻止。
- 自定义库与内置库分离，插件升级不会覆盖用户数据。

### 8.2 更多安装结构

按实际需求优先考虑：

- 方螺母与 T 形螺母槽。
- 捕获螺母的侧向装配通道。
- 垫圈及法兰螺母。
- 攻丝预孔策略，与直接咬合明确区分。
- 同一宿主内的轴向分段孔。

每类结构都应先定义装配语义和切割规则，再加入类型选择，避免退化为任意几何生成器。

### 8.3 块与协作模型支持

逐步完善：

- Rhino Block 实例内组件的安全识别。
- Worksessions、引用模型和只读宿主的明确状态。
- 从链接模型读取位置但把参数化组件保存在当前文档。

这类能力应以不修改外部文件为原则。

## 9. 视觉与交互品质路线

### 9.1 主面板改为“任务驱动”层级

建议保持三个稳定区域：

1. 顶部：模板摘要与当前选择摘要。
2. 中部：当前类型真正需要的参数。
3. 底部：统一图标操作栏。

避免继续增加永久可见区块。次要功能进入“更多”、上下文菜单或独立对话框。

### 9.2 建立完整设计令牌

将间距、字号、控件高度、边框、状态色和图标尺寸统一为设计令牌，并覆盖：

- 浅色与深色主题。
- 100%–200% DPI。
- 280–500 DIP 面板宽度。
- 正常、悬停、按下、禁用、焦点和错误状态。

所有动态模块必须使用同一主题组件，不在业务代码中直接写颜色和尺寸。

### 9.3 统一状态反馈

推荐使用三层反馈：

- 视口：即时位置和几何结果。
- 面板顶部：一句短状态。
- 问题中心/命令行：完整原因和修复建议。

成功消息短暂显示后恢复选择摘要；错误状态持续到用户修复或取消。

### 9.4 微动效与可感知响应

只使用功能性动效：

- 卡片选择变化使用轻微颜色过渡。
- 智能预览有效/无效切换平滑改变轮廓色。
- 更新完成后控制点短暂高亮。
- 长时间布尔显示阶段进度和当前宿主。

不使用装饰性动画，不影响 Rhino 视口帧率。

## 10. 性能与工程质量

### 10.1 文档级空间索引

复杂文档中智能摆放和长度更新不应每次扫描全部对象。建议建立可失效重建的宿主空间索引：

- 对象新增、删除、变换时增量更新。
- 鼠标移动先用空间索引过滤，再做精确 Brep 求交。
- 预览几何按类型、规格和参数签名缓存。

### 10.2 可取消的预检和导出

批量更新、检查和导出提供进度与取消：

- 计算阶段可取消且零写入。
- 写入阶段保持原子提交。
- UI 不阻塞 Rhino 主线程；几何 API 必须在 Rhino 要求的线程边界内调度。

### 10.3 诊断包

增加“导出诊断信息”功能，生成不含模型几何的 ZIP：

- 插件、Rhino 和 .NET 版本。
- 文档单位和容差。
- 匿名化组件参数、错误代码和操作阶段。
- 最近一次布尔失败摘要。

文件路径、对象名称和用户备注默认脱敏，由用户确认后再提交问题。

### 10.4 自动化基线

建议在发布前固定以下门槛：

- 核心单元测试全通过。
- schema v1 至当前版本的迁移样本全部通过。
- 已知平面、倾斜、曲面和薄壁几何的 Rhino 集成测试通过。
- 100、500、1000 个组件的放置、选择、更新和导出性能基准不退化。
- 浅色/深色、常用宽度与 DPI 的截图回归通过。
- 插件加载、工具列、兼容检查和打包产物校验通过。

## 11. 建议版本节奏

### 0.30：快速编辑

- 视口快速编辑器。
- 参数手柄第一版。
- 最近使用、收藏模板和重复上一操作。
- 面板任务层级进一步收敛。

### 0.31：批量效率

- 点集批量放置。
- 阵列感知工作流。
- 组件导航器和批量预检摘要。
- 文档级宿主空间索引。

### 0.32：装配可靠性

- 装配检查器。
- 自动长度建议。
- 装配关系可视化。
- 重新绑定向导与输出中心。

### 0.33：交付与扩展

- 物料清单和交付快照。
- 用户自定义紧固件库。
- 根据真实需求增加新的螺母/垫圈结构。

### 1.0：稳定版

- 冻结组件 schema 和主要命令行为。

- 完善安装、更新、卸载、故障诊断和示例模型。
- 发布完整用户手册、快速入门和典型装配案例。

## 12. 衡量是否真的变得更好

建议用以下指标检验每个版本，而不只统计新增功能：

| 指标 | 建议目标 |
| --- | --- |
| 已设置模板后的单颗智能放置 | 1 次点击完成 |
| 修改单颗螺丝规格或长度 | 选中后不超过 2 次操作 |
| 批量更新一组控制点 | 设置模板后 1 次更新 |
| 常用模板再次使用 | 不超过 2 次操作 |
| 320 DIP 宽面板 | 无横向滚动条 |
| 常见 800–960 DIP 高度 | 高频参数和操作栏无需纵向滚动 |
| 100 个组件选择与摘要刷新 | 用户无明显等待感 |
| 更新或导出失败 | 零部分写入，提供具体对象和修复动作 |
| 浅色/深色主题 | 信息层级、焦点和状态含义一致 |

## 13. 当前最值得先做的三件事

1. **批量点位放置与阵列工作流**：复用 0.30.0 的不可变操作快照，把多孔设计从重复点击升级为可预检的批处理。
2. **组件导航器与问题中心**：让复杂文档中的筛选、定位、批量选择和待重绑问题更易管理。
3. **装配检查器与长度建议**：在不涉及承载结论的前提下，减少长度、碰撞和操作空间错误。

这三项完成后，插件的体验会从“功能很多的参数面板”转变为“围绕 Rhino 视口工作的紧固件装配助手”，也更适合作为 1.0 版本的核心产品定位。
