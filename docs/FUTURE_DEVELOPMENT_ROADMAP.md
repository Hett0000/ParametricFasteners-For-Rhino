# 参数化紧固件未来发展路线

> 基于版本：`0.38.7`
>
> 更新日期：2026-08-24
>
> 目标：通过 `0.36 → 0.37 → 0.38` 三个阶段进入 `1.0` 稳定版。

## 1. 产品当前判断

参数化紧固件已经具备完整的“设置、放置、修改、检查、交付”能力。当前限制产品体验的主要因素不再是紧固件类型不足，而是功能持续扩展后产生的状态路径、操作入口和理解成本：

- 同一参数会参与模板、组件、预览、宿主绑定、切割模块和导出结果，任何路径不同步都会产生难以发现的错误。
- 主面板、快速小窗、参数手柄、导航器和检查器分别承担编辑职责，用户需要理解不同入口的边界。
- 批量工具已经能够处理大量组件，但仍需要用户逐颗判断长度、装配方式和异常处理方案。
- 输出、统计和装配检查已经足够完整，继续堆叠低频功能的收益低于提高核心流程可靠性。

因此，进入 1.0 之前不再以“增加更多参数和紧固件类型”为主线，而是依次完成：

1. 统一组件状态、几何和事务。
2. 收敛编辑入口并增强视口表达。
3. 用可确认、可撤销的建议提高个人建模效率。

## 2. 路线总览

| 阶段 | 核心目标 | 用户直接收益 | 发布条件 |
| --- | --- | --- | --- |
| `0.36` | 可靠内核与文档自愈（已实现） | 预览、模型和导出始终一致，异常模型可安全恢复 | 状态单一、事务统一、健康检查可用 |
| `0.37` | 上下文编辑与交互收敛（已实现） | 更少入口、更少滚动，选中后立即理解和修改 | 高频任务不超过三次明确操作 |
| `0.38` | 智能装配加速（已实现） | 自动提出长度和装配候选，重复位置可批量处理 | 建议可追溯、可覆盖、一次确认提交 |
| `1.0` | 稳定发布 | 核心行为冻结，安装、建模和交付形成稳定产品 | 完整支持矩阵与固定回归模型通过 |

## 3. 0.36：可靠内核与文档自愈

### 3.1 目标

消除预览、组件代理、切割模块和导出结果不同步的根本风险。无论操作来自主面板、快速编辑、参数手柄、复制变换还是批量工具，都必须进入同一状态与事务管线。

### 3.2 单一可信状态

- 建立不可变的 `FastenerComponentSnapshot`，由控制点元数据生成，作为组件参数、放置坐标、宿主绑定和尺寸快照的唯一可信输入。
- 面板草稿、快速编辑草稿、预览对象、文档索引和缓存全部视为可丢弃运行时状态，不得反向覆盖控制点中的已保存组件数据。
- 为快照生成稳定参数签名；预览、组件代理和导出必须记录并校验同一签名。
- 文档中的切割预览对象不再承担几何事实来源，缺失、隐藏或过期时能够从快照完整重建。

### 3.3 统一事务

- 建立 `ComponentOperationPlan`，统一执行：`读取快照 → 解析规格 → 识别宿主 → 构建几何 → 完整校验 → 提交或回滚`。
- 放置、单点/批量更新、复制规范化、移动/旋转/镜像同步、重绑、删除和修复全部复用该计划。
- 所有写操作先完成全量预检；成功时只产生一次 Undo，任何一步失败时零写入。
- Rhino、STEP、STL 和渲染紧固件输出直接消费已经验证的几何准备结果，不再各自推导参数。

### 3.4 文档健康与自愈

- 文档打开后执行非破坏健康检查，汇总正常、可确定重建、待重新绑定和数据/几何损坏四类状态。
- 健康检查不得自动删除或重新绑定对象；用户确认后才执行“一键修复可确定问题”。
- 控制点存在且数据有效时，允许重建缺失的代理、切割预览、材质引用和内部组。
- 宿主候选唯一时可以列为可确定修复；候选歧义时必须进入显式重绑流程。
- 文档切换、Undo/Redo、复制、粘贴和异常中断后，编辑会话与缓存能够从控制点重新建立。

### 3.5 错误与可诊断性

- 错误统一包含组件、宿主、操作阶段、短原因和可执行建议。
- 面板显示一行短错误，命令行保留完整信息并支持定位到对应控制点或宿主。
- 相同错误使用稳定问题代码，装配检查器、维护中心和输出中心共享同一解释。
- 不增加独立诊断包或联网收集；诊断信息保持本地、按需显示。

### 3.6 完成标准

- 固定回归矩阵中，动态预览、组件代理、切割预览和 Rhino/STEP/STL 的参数签名与有效几何一致。
- 所有失败写操作零部分写入，成功写操作只产生一次 Undo。
- 删除全部可重建预览对象后，组件仍能读取、更新、检查和导出。
- Yak 安装后连续启动 Rhino 十次，插件命令、面板和工具栏每次均可用。
- 500 个组件文档中，选择摘要、导航和健康状态使用索引增量更新，不因同步全量扫描阻塞界面。

## 4. 0.37：上下文编辑与交互收敛

### 4.1 目标

让用户始终清楚三个问题：当前模板是什么、当前选中了什么、下一次操作会修改什么。减少重复入口和不必要的二级窗口，但保持“场景选择只指定目标，读取操作才覆盖模板”的既有安全语义。

### 4.2 主面板信息架构

- 顶部明确区分 `创建模板` 和 `选择目标`：前者表示即将用于放置或更新的参数，后者表示当前选中的组件数量、类型、规格和健康状态。
- 参数按“基础尺寸、装配方式、孔与切割”渐进显示；不适用于当前类型的字段不占据布局空间。
- 高频参数始终可见，低频显示、交付和高级工艺参数进入紧凑弹层。
- 底部八项操作继续保留，但 Tooltip、禁用原因和右击能力使用统一文案。
- “更多…”改为可搜索的分组菜单：编辑、检查、输出、管理和设置。

### 4.3 统一上下文编辑

- 单选控制点后显示统一上下文编辑条，集中提供快速修改、读取到模板、删除、应用和取消。
- 快速小窗、主面板和参数手柄共享 `ContextualEditDraft` 与同一预检结果，不再分别维护参数同步规则。
- 用户取消编辑时只丢弃草稿；确认后进入 0.36 的统一事务。
- 多选时上下文编辑条切换为批量摘要，只显示能够安全批量应用的参数和操作。

### 4.4 视口反馈

- 快捷编辑草稿继续用半透明代理和切割轮廓表达即将提交的结果。
- 穿过体、咬合体、安装槽和异常宿主使用稳定颜色与短标签。
- 错误和警告在对应控制点或宿主位置高亮，不创建文档对象。
- 不提供插件剖切视图；需要截面核对时使用 Rhino 原生剖切或导出的布尔副本。

### 4.5 视觉与输入一致性

- 主面板和所有二级窗口继续采用统一浅色/深色主题、系统字体和语义状态色。
- 280 DIP 宽度不得出现横向滚动条；长文本省略并通过 Tooltip 或详情区查看。
- 常见 800–960 DIP 高度下，高频参数、选择摘要和底部操作无需滚动即可使用。
- Enter、Esc、键盘焦点、按钮顺序和禁用原因在全部窗口保持一致。

### 4.6 完成标准

- 放置、单颗修改、批量更新、读取和检查均不超过三次明确操作。
- 选择有效控制点后 150 ms 内显示上下文摘要。
- 常用双板螺纹咬合装配无需打开二级窗口即可完成设置、放置和修改。
- 用户仅凭顶部摘要、宿主颜色和按钮状态即可判断下一次更新的目标与参数来源。
- 浅色、深色、100%–200% DPI及 280–500 DIP 面板宽度下信息层级一致。

## 5. 0.38：智能装配加速

### 5.1 目标

减少逐颗判断长度、装配方式和重复位置的工作。自动化只提出候选，不直接修改模型；用户确认后才进入统一事务。

### 5.2 装配建议

- 增加只读 `AssemblySuggestion`，根据宿主层级、轴向厚度、可用咬合深度、边界空间和当前模板提出装配方式、螺杆长度、孔深/露出量和配套螺母位置。
- 每条建议显示测量依据、当前值、建议值、风险和可覆盖字段。
- 歧义宿主、重叠实体和无法可靠测量的几何只返回阻断原因，不生成猜测结果。
- 装配建议与装配检查器共享同一套几何测量服务，避免出现互相矛盾的结论。

### 5.3 重复位置与批量放置

- 从用户选中的 Rhino Point、圆、圆边、孔中心、规则点集和重复面特征提取候选位置。
- 所有来源统一进入现有批量预检，不直接创建组件。
- 预检表格允许每个位置使用独立建议长度，同时共享类型、规格、装配方式和切割策略。
- 用户可以逐行覆盖建议，也可以按状态筛选后批量采用。
- 一次确认生成全部通过项，一次 Undo 撤销整批结果。

### 5.4 自适应批量更新

- 批量更新增加“统一参数、长度按宿主自适应”模式。
- 类型、规格、装配方式和孔策略来自当前模板；每颗组件根据自身宿主重新计算长度。
- 装配检查器增加“处理所选建议”，在提交前列出每颗组件的当前值、建议值和最终采用值。
- 用户可保留当前长度、采用建议或输入覆盖值；任一组件预检失败时整批零写入。

### 5.5 装配方案

- 收藏模板升级为可选的“装配方案”，保存紧固件类型和规格、装配方式、孔径与孔深策略、螺母/热熔/架桥参数以及常用输出方案引用。
- 装配方案不保存宿主、组件 ID、控制点或文档路径。
- 载入方案只改变当前模板，不立即修改场景组件。

### 5.6 完成标准

- 典型重复孔阵列通过一次候选提取、一次预检和一次确认完成。
- 不同宿主厚度的批量组件能够采用不同且可解释的建议长度。
- 所有建议均可追溯、覆盖、取消和撤销，不存在无提示自动写入。
- 批量建议、装配检查和最终导出使用一致的宿主测量与组件参数。
- 100 个候选点位的预检持续显示进度，并可在安全边界取消且零写入。

## 6. 1.0：稳定发布

### 6.1 核心冻结

- 冻结组件角色、参数含义、控制点生命周期、公开命令名称和事务边界。
- 已有 3DM 组件、模板和公开命令继续兼容；后续 schema 变化必须提供确定迁移。
- 预览、组件代理和输出共享同一几何准备管线，禁止新增绕过入口。

### 6.2 功能收口

- 自定义标准件库结束 Beta：通过实际项目验证后转为正式功能；若来源、升级和交换流程仍不稳定，则从主要入口移出并继续实验。
- 固定支持的紧固件、装配模式、Rhino版本、文件格式和已知限制。
- 完成安装、升级、故障恢复、建模、检查、重绑和交付文档。

### 6.3 发布验证

- 固定双板、多层、只咬合、螺母固定、热熔螺母、批量点位和复杂变换测试模型。
- 验证安装、重启、放置、更新、复制、移动、旋转、镜像、检查、重绑、统计和全部输出闭环。
- 验证浅色/深色、100%–200% DPI、280–500 DIP 面板和大型组件文档。
- 1.0 后优先修复稳定性和适配 Rhino 新版本，新紧固件类型只按高频、可验证需求加入。

## 7. 功能必要性

| 优先级 | 功能方向 | 结论 |
| --- | --- | --- |
| 最高 | 单一状态源、统一事务、文档自愈 | 直接解决历史上最常见的预览、更新和导出不一致问题，必须先完成。 |
| 最高 | 上下文编辑与直接视口反馈 | 减少参数修改路径和目标误解，同时避免额外剖切状态增加操作负担。 |
| 高 | 几何感知长度建议 | 已有检查和宿主测量基础，能直接减少逐颗试错。 |
| 高 | 重复位置识别、自适应批量更新 | 对个人设计效率提升明显，并可复用现有批量预检与事务。 |
| 高 | 装配方案 | 能减少重复设置，但必须建立在参数和状态已经收敛之后。 |
| 延后 | 团队审批、跨成员标准库、项目权限 | 面向组织管理，当前优先级低于个人建模效率和稳定性。 |
| 延后 | 复杂交付版本管理和快照历史 | 当前原子输出已覆盖主要交付风险，等待真实项目需求。 |
| 需求驱动 | 新增紧固件类型 | 只有具备可靠尺寸来源、明确装配语义和高频案例时才加入。 |
| 需求驱动 | Block、Worksessions、外部引用 | 涉及跨文件所有权和生命周期，先收集可复现企业案例。 |
| 不开发 | 真实螺纹几何 | 会降低布尔稳定性、交互性能和 FDM 实用性。 |
| 不开发 | 承载能力计算和打印机校准 | 超出当前几何装配工具的可信边界。 |
| 不开发 | 云端社区与默认上传 | 引入隐私、审核和持续运维，不符合本地 Rhino 工具定位。 |
| 不开发 | 无确认自动修改 | 所有智能建议必须经过用户确认并支持撤销。 |
| 不开发 | 持续装饰动画 | 只保留定位、错误、成功和进度等功能性反馈。 |

## 8. 跨阶段工程原则

### 8.1 数据与状态

- 控制点组件数据是持久化事实来源，其他对象和缓存必须可重建。
- UI 草稿、建议和预检结果不得自动覆盖已保存组件。
- 组件、模板和用户库的职责保持分离，避免同一字段出现多个权威来源。

### 8.2 事务与安全

- 写操作必须先完整预检，再一次提交。
- 失败或取消不得留下临时对象、材质、组、选择状态或部分输出文件。
- 任何自动修复和智能建议都必须可解释、可确认和可撤销。

### 8.3 性能与响应

- 鼠标移动和场景选择不得同步扫描整个文档。
- 文档索引按对象事件增量失效和重建。
- 长任务显示阶段、完成数量、总进度和取消入口，并只在安全边界停止。
- 性能验收使用固定测试模型和硬件记录，避免只用主观“流畅”判断。

### 8.4 隐私与边界

- 插件默认完全本地工作，不上传模型、组件、模板或文件路径。
- 不提供未经验证的承载、强度或打印质量结论。
- 自动化宁可明确停止，也不对歧义宿主和不可靠几何进行猜测。

## 9. 可量化体验指标

| 指标 | 目标 |
| --- | --- |
| 已设置模板后的单颗智能放置 | 一次点击创建 |
| 单颗常用参数修改 | 选中后不超过三次明确操作 |
| 批量模板更新 | 设置模板后一次确认 |
| 重复位置装配 | 一次提取、一次预检、一次创建 |
| 选择到上下文反馈 | 固定测试文档中不超过 150 ms |
| 280 DIP 主面板 | 无横向滚动条 |
| 常见 800–960 DIP 高度 | 高频参数和操作栏直接可见 |
| 失败写操作 | 零部分写入 |
| 成功写操作 | 一次 Undo 完整撤销 |
| 长任务取消 | 下一个安全边界停止且无残留 |
| 安装稳定性 | Yak 安装后连续十次启动无命令或工具栏丢失 |
| 几何一致性 | 预览、组件代理与三类输出使用相同有效参数和几何签名 |

## 10. 阶段进入与退出条件

### 0.36（已完成）

- 进入：0.35.5 安装链稳定，现有回归测试通过。
- 退出：控制点快照、统一几何准备、事务回滚、派生签名与只读健康扫描已经落地；后续可靠性缺陷继续作为回归修复处理。

### 0.37（已完成）

- 进入：0.36 的状态与事务接口冻结，UI 不再需要绕过统一管线。
- 退出：主面板和上下文编辑通过高频任务及响应式验收；0.37.2进一步移除低频入口，并完成轻量悬停、精确点击提交的智能放置性能优化。

### 0.38（已完成）

- 进入：宿主测量、检查结果和组件更新已经使用相同数据来源。
- 退出：统一拾取射线、装配测量与建议、重复位置提取、逐点采用长度、自适应批量更新和装配方案 schema 已落地；后续以 Rhino 实际项目反馈作为 1.0 收口依据。

### 1.0

- 进入：0.36–0.38 的用户流程稳定，自定义标准件库已决定正式保留或降级。
- 退出：固定回归模型、安装矩阵、交互矩阵和全部输出闭环通过，核心行为正式冻结。

## 11. 执行顺序

1. 0.36–0.38 已完成，下一阶段进入 1.0 核心冻结与实际项目验证。
2. 继续复用统一测量、检查、建议和更新服务，不建立第二套智能逻辑。
3. 新增功能必须先证明不会破坏一次 Undo、失败零写入和几何一致性。
4. 历史版本继续由 Release 文档记录，本 Roadmap 只描述当前判断和未来工作。
